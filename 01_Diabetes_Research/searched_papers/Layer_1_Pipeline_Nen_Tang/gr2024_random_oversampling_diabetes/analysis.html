Tổng quan & vì sao thuộc Layer 1

Paper đề xuất một mô hình e-diagnosis chạy trên IoMT (Internet of Medical Things) để phân loại đái tháo đường (diabetes) trên dữ liệu dạng bảng (tabular). Trọng tâm thật sự là một pipeline tiền xử lý + cân bằng lớp + chọn feature rồi so sánh 4 model ML cây (tree-based). Quy trình: mean imputation cho missing → IQR loại outlier → random oversampling cân bằng lớp → chọn feature bằng PCA hoặc Boruta → huấn luyện RF / GBC / LightGBM / DT → đánh giá bằng Accuracy, Precision, Recall, F1, AUC-ROC + 10-fold CV. Cấu hình thắng cuộc là Boruta + Random Forest với tỉ lệ test 20%, đạt 94% accuracy trên PIDD và 92% trên BRFSS (Section 5; Table 6, 9).

Công thức quan trọng

IQR outlier removal (Section 4.1) IQR = Q3 − Q1
lower = Q1 − 1.5 × IQR
upper = Q3 + 1.5 × IQR
→ loại mọi giá trị < lower hoặc > upper
Metrics đánh giá (Section 4.3.5, Eq. 31–33) Accuracy = (TP + TN) / (TP + TN + FP + FN)
Precision = TP / (TP + FP)
Recall = TP / (TP + FN)
F1 = 2 · Precision · Recall / (Precision + Recall)
Boruta — phân biệt feature (Section 4.2.2) Tạo "shadow features" bằng hoán vị giá trị mỗi cột → gắn vào ma trận gốc → train RF
Z_Score(feature) > S_max(shadow) ⇒ feature CÓ Ý NGHĨA
Z_Score(feature) < S_max(shadow) ⇒ feature LOẠI BỎ

Lưu ý quan trọng

⚠️ Rủi ro data leakage & accuracy có thể thổi phồng
  • Paper không nêu rõ oversampling/imputation/feature-select fit trước hay sau split — Section 4.1 mô tả oversampling trước khi nói tới split → khả năng oversample toàn bộ data rồi mới split, làm rò rỉ test set và đẩy accuracy lên cao giả tạo.
  • Tự thừa nhận random oversampling "can result in overfitting … too biased toward the minority class" (Section 4.3.5) — cần kết hợp CV + regularization.
  • Recall BRFSS 10-fold CV = 98.05% nhưng Precision chỉ 88.06% (Table 8) → mô hình kéo recall lên cao (có thể do oversample), nên xem lại confusion matrix gốc.
🎯 Giới hạn của paper
  • PIDD chỉ 768 mẫu, toàn nữ PIMA Indian → khó khái quát; BRFSS là survey self-report → có recall bias.
  • Không nêu số mẫu cuối của BRFSS và không nêu số mẫu sau loại outlier/oversample.
  • Claim "cao hơn 3% so với nghiên cứu hiện có" (Abstract) không khớp Table 9: 94 − 89.46 (XRL) ≈ 4.5%; còn so baseline yếu hơn thì chênh tới ~20%. Mốc so sánh mơ hồ.
  • Không external validation trên dữ liệu bệnh viện độc lập; IoMT/e-diagnosis chỉ mô tả khái niệm, không deploy/đo được.
  • Không công bố code (Data Availability chỉ có link 2 dataset); hyperparam RF/Boruta không liệt kê → tái lập chính xác khó.
💡 Vai trò trong đề tài (Layer 1)
  • Là pipeline-baseline gọn: imputation → IQR → oversampling → Boruta → RF, để các layer sau so chiếu.
  • So peer Layer 1: accuracy PIMA cao hơn hennebelle2023 (0.94 vs 0.78 — họ tối ưu MLOps/deployment chứ không tối ưu accuracy) và thấp hơn abnoosian2023 (0.99 trên IPDD — khác bài 3-lớp, đơn-dataset). Cấu hình bài này nhị phân, đa-dataset, đơn giản nhất.
  • Cơ hội cải tiến: (1) sửa thứ tự pipeline để chống leakage rồi đo lại; (2) thay random oversampling bằng SMOTE/ADASYN; (3) thêm ensemble/stacking để vượt 94%; (4) thêm XAI (SHAP) giải thích RF — đúng định hướng Layer 4.
  • Kết quả 94% chỉ nên xem là sàng lọc (screening), không thay chẩn đoán y khoa.
